# Часть A. Зачем этот продукт и какая планка

## A1. North star (одно предложение)

Оператор заходит в кабинет и **без документации и без разработчика** понимает состояние лаборатории, принимает решения по предложениям агентов и видит последствия в деньгах, стратегиях и журнале — на русском, с объяснениями «почему».

## A2. Кого мы делаем лучше (планка «инструмент №1»)

Мы не конкурируем с TradingView или приложением брокера. Мы конкурируем с ощущением «кривой админки своего бота».

| Класс инструмента | Что берём | Что не берём |
|---|---|---|
| Операторские консоли (внутренние desk-tools) | Иерархия внимания, статусы всегда видны, опасные действия с confirm | Перегруз метриками |
| Хорошие bank/fintech apps | Деньги и статусы человеческим языком, пустые состояния с next step | Маркетинговый fluff |
| Linear / Notion (onboarding) | Короткий тур по якорям, можно пройти снова | Навязчивый cheerleading |
| Плохие «AI dashboards» | — | Фиолетовый glow, EN-лейблы, 20 KPI, JSON на главной |

**Критерий «максимум»:** человек, который видел только ТЗ бэкенда, после Помощи + туров на Обзоре и Агентах может объяснить вслух: что такое сейф, рукав, предложение и стоп.

## A3. Jobs to be done (с критерием успеха)

| ID | Работа | Успех за сессию |
|---|---|---|
| J1 | Убедиться, что контур жив и торговля не в стопе | < 5 сек с любого раздела по шапке |
| J2 | Понять, где деньги | назвать стоимость счёта / кэш / сейф и фазу сейфа |
| J3 | Понять, что делают стратегии | сравнить рукава и открыть ленту сигналов одного |
| J4 | Решить по агенту | принять или отклонить proposal и увидеть новый статус |
| J5 | Связать новость с тикером/research | найти новость, открыть study или честно увидеть empty |
| J6 | Понять отказ | в ордере видна русская причина risk gate |
| J7 | Аварийный стоп | включить/снять стоп только через confirm, статус в шапке |
| J8 | Научиться пользоваться | пройти тур раздела без внешних объяснений |
| J9 | Доверять цифрам | видна свежесть данных и оговорка «paper-книга ≠ брокерский UI» |

## A4. Модель внимания (что важнее чего)

Приоритет на любом экране сверху вниз:

1. **Блокирующее:** нет токена / 401 / система недоступна / стоп включён  
2. **Требует действия:** предложения «ждут решения»  
3. **Капитал:** стоимость счёта и изменения смысла (сейф, кэш)  
4. **Стратегии:** аномалия PnL / свежие сигналы  
5. **Справочное:** вселенная, ledger, help  

Если на Обзоре одновременно «стоп» и «3 предложения» — оба видны, но стоп визуально сильнее (нельзя «не заметить»).

## A5. Принципы прозрачности (обязательные паттерны)

Каждый блок данных обязан уметь ответить на 4 вопроса (в UI, не в голове разработчика):

1. **Что это?** — подпись + «Что это?» / tooltip  
2. **Откуда?** — paper-книга / воркер / агенты / новости (короткая строка «источник»)  
3. **Насколько свежо?** — «обновлено только что» / время воркера / «нет сигнала от воркера»  
4. **Что делать, если пусто/плохо?** — next step со ссылкой в раздел  

Запрещён паттерн: молчаливый `0,00` без пояснения контекста.

## A6. Антипаттерны (сдача этапа запрещена, если есть)

- Английские пользовательские лейблы (`Equity`, `Kill`, `Ledger`, `Sleeve` как заголовок)
- Одна длинная страница «всё сразу» как финальный UX
- JSON proposal на первом уровне без human summary
- Кнопка Стоп без confirm
- Тур только на Обзоре, на остальных экранах «как-нибудь»
- Empty «нет данных» без причины и next step
- Смешение paper-книги и «как будто это Тинькофф в браузере»
- Декоративные KPI, которые нельзя объяснить оператору за 10 секунд
- Скрытие ошибки сети под нулями
- Разные слова для одного понятия на разных экранах

## B2. Глобальный chrome (на 100% страниц после входа)

```
┌─────────────────────────────────────────────────────────────┐
│ i.datagon  [песочница]     пиллы статуса     [N ждут] [↻]  │
│                            Стоп / Снять стоп   токен ▾     │
├────────┬────────────────────────────────────────────────────┤
│ Меню   │  Заголовок раздела          [Обучение] [Как читать]│
│        │  intro 1–2 фразы                                   │
│        │  ─────────────────────────────────────────────     │
│        │  контент раздела                                   │
└────────┴────────────────────────────────────────────────────┘
│ нижняя полоса: «данные paper-книги · обновлено …» (desktop) │
```

### Пиллы статуса (точный смысл)

| Пилл | Зелёный | Янтарный | Красный |
|---|---|---|---|
| Система | `/status` или `/ready` ок | деградация (редко) | нет ответа / 5xx |
| Воркер | `worker_alive=true` | нет heartbeat / stale | — (янтарь достаточный) |
| Торговля | стоп выключен («можно выставлять») | — | стоп включён («новые ордера запрещены») |
| Агенты | включены | выключены (не ошибка!) | — |

Янтарный «агенты выключены» — **информационный**, не аварийный. Текст: «Агенты выключены — очередь будет пустой, это нормально».

### Свежесть данных

- В шапке/подвале: время последнего успешного обновления UI.  
- Рядом с воркером: `worker_beat` человечески («пульс 2 мин назад»).  
- Если запрос раздела упал — блок показывает ошибку, остальные блоки живут.

## B3. Словарь (единый, расширенный)

| Код | UI | Подсказка «Что это?» (коротко) |
|---|---|---|
| equity | стоимость счёта | Кэш + сейф + оценка позиций в paper-книге |
| cash | свободный кэш | Деньги на торговом счёте книги, ещё не в позициях/сейфе |
| vault | сейф прибыли | Доля зафиксированной прибыли, которую лаборатория откладывает |
| sleeve | рукав | Отдельная стратегия со своим учётом сигналов и PnL |
| realized | зафиксировано | PnL уже зафиксированный сделками |
| unrealized | на бумаге | Переоценка открытых позиций |
| deposit | депозит | Стартовое пополнение лаборатории (цель перекрытия сейфа) |
| drift | расхождение | Разница между книгой и кэшем sandbox, если он известен |
| universe | вселенная | Список бумаг, по которым вообще разрешено думать о входе |
| proposed | ждут решения | Агент предложил — без тебя ордер/веса не применятся |
| killed | стоп включён | Risk gate режет новые ордера |

Reason коды ордеров → русские фразы (этап 21 обязан закрыть словарь полностью):

| reason (пример) | Показать оператору |
|---|---|
| `killed` | Отклонено: включён стоп торговли |
| universe / not in universe | Отклонено: тикера нет в активной вселенной |
| name / weight | Отклонено: слишком большая доля одной бумаги |
| sleeve | Отклонено: превышен лимит капитала рукава |
| daily | Отклонено: сработал дневной лимит убытка |
| once / once_per_bar | Отклонено: повторный вход в тот же бар |
| earnings | Отклонено: день отчёта эмитента (veto) |

# Часть C. Чертежи экранов (что именно на страницах)

Ниже — **обязательный состав**. Убрать блок = изменить ТЗ. Добавлять можно только если не ломает внимание §A4.

## C1. Экран входа (до меню)

**Заголовок:** «Вход в кабинет i.datagon»  
**Текст:** «Нужен токен кабины из вашего `.env` (`APP_AUTH_TOKEN`). Это не токен Тинькоффа и не пароль брокера.»  
**Поля:** токен (password), чекбокс «запомнить на этом устройстве» (по умолчанию да = localStorage).  
**Кнопка:** «Войти в кабинет».  
**Ошибки:**
- пусто → «Вставьте токен кабины»  
- 401 → «Токен не принят. Проверьте `APP_AUTH_TOKEN` и что API запущен.»  
- сеть → «Нет связи с API на этом адресе.»  

**Обучение (мини-тур 2 шага):** токен кабины vs брокер; что будет после входа.

## C2. Обзор `#/overview`

**Intro:** «Сводка лаборатории: живость системы, деньги, решения, которые ждут вас, и состояние рукавов.»

Зоны (строго в этом порядке):

1. **Внимание** — если стоп: баннер «Торговля остановлена»; если proposed>0: баннер «Есть предложения, которые ждут решения» с CTA.  
2. **Капитал** — 3 крупные метрики: стоимость счёта, свободный кэш, сейф (+ ссылка «Подробнее в Портфеле»).  
3. **Очередь решений** — до 3 карточек proposed (тип, суть одной строкой, CTA «Открыть») или empty.  
4. **Рукава** — компактная таблица PnL, клик → Стратегии/рукав.  
5. **Не класть:** полный ledger, все новости, вселенную целиком.

**Тур Обзора (обязательные шаги):**
1. Пиллы статуса  
2. Баннер внимания (или «здесь появится, если что-то горит»)  
3. Капитал  
4. Очередь агентов  
5. Рукава  
6. Меню слева («куда идти дальше»)

## C3. Портфель `#/portfolio`

**Intro:** «Paper-книга лаборатории: где лежат деньги и какие позиции открыты. Это не экран приложения брокера.»

Вкладки:

### Капитал
- стоимость счёта / кэш / сейф  
- строка источника: «Источник: journal проводок + позиции»  
- оговорка paper vs брокер  

### Позиции
Колонки: рукав · тикер · количество · средняя цена · оценка (если есть) · доля (если считаем)  
Empty: «Позиций нет. Стратегия ещё не входила в рынок. Откройте Стратегии → сигналы, чтобы понять, были ли решения.»

### Сейф
- депозит, накоплено, фаза («сейчас откладываем 50% / 20%»), остаток до перекрытия  
- прогресс до перекрытия депозита  
- текст правила простым языком (2–3 предложения, без формул в лоб; формулу — под «Как считается»)

### Аллокация
- рукав · доля · капитал рукава · потолок sleeve_share пояснением  
- empty если equity=0 с объяснением  

### Расхождение
- книга vs sandbox cash  
- если sandbox cash неизвестен: честный empty «Нет данных кэша sandbox для сравнения. Расхождение появится, когда оператор/контур передаст сумму.»  
- не показывать фейковый 0 как «всё сходится»

**Тур:** капитал → оговорка paper → сейф → аллокация → расхождение.

## C4. Стратегии `#/strategies`

**Intro:** «Рукава — отдельные стратегии на общих свечах. Здесь сравнение и лента решений на дневном закрытии.»

### Сравнение
Колонки: название · код · зафиксировано · на бумаге · итог · «открыть»  
Человекочитаемые имена: `sma_cross` → «Пересечение средних», `donchian_breakout` → «Пробой Дончиана» (код вторичен).

### Карточка рукава
- PnL блок  
- кратко «как устроен» (1 абзац, статический текст per sleeve)  
- лента сигналов: время · тикер · действие · (payload под катом)  
- фильтры: тикер, тип действия  
- empty дифференцированный:
  - воркер молчит → «Нет пульса воркера — сигналы могут не обновляться. Проверьте, что воркер запущен.»  
  - воркер жив, сигналов 0 → «За выбранный период решений не было.»  

**Тур:** что такое рукав → как читать PnL → как читать сигнал → фильтры.

## C5. Агенты `#/agents`

**Intro:** «Агенты только предлагают. Сделка или смена весов — после вашего „Принять“ и прохождения риск-правил.»

Зоны:
1. Баннер состояния агентов (вкл/выкл) — никогда не маскировать под ошибку, если выкл.  
2. **Ждут решения** (proposed) — крупные карточки.  
3. **Недавние решения** — approved/rejected/expired.  

### Карточка предложения (обязательные поля)
- заголовок: «Предложение ордера» / «Предложение весов»  
- статус-чип  
- human summary (обязательно, не JSON):
  - order: сторона, тикер, кол-во, рукав, стоп если есть, reason кратко  
  - weights: список рукав→вес  
- блок «Что будет при „Принять“» (1–2 предложения)  
- кнопки Принять / Отклонить  
- «Подробнее» → JSON payload  

После Принять: если ордер rejected risk gate — показать это **явно** («принято вами, но риск отклонил ордер: …»), не прятать успех approve.

**Тур:** агент не торгует сам → карточка → принять/отклонить → где смотреть итог в Журнале.

## C6. Новости `#/news`

**Intro:** «Внешний информационный контур. Новости не открывают сделки сами. Research считается offline и без подглядывания в будущее.»

Вкладки: Лента | Исследования  

Лента: время · источник · заголовок · тикеры-чипы · открыть источник  
Фильтр по тикеру; поиск по заголовку (клиентский ok).  
Чип тикера → фильтр или переход в Стратегии.

Studies: новость/тикер · окно · результат кратко · empty «Ещё не считалось».

**Тур:** лента ≠ торговые сигналы → тикеры → research → ограничение lookahead простым языком.

## C7. Рынок `#/market`

**Intro:** «Периметр торговли: какие бумаги допущены и какие правила режут ордера.»

### Вселенная
Таблица: тикер · статус активна · причина (по-русски, маппинг reason) · обновлено  
Сводка: «В вселенной N бумаг (лимит M)».  
Empty: «Состав ещё не наполнен ситом. Пока вселенная пуста, входы будут отклоняться.»

### Правила риска
Чеклист-карточки (не простыня кодекса):
- стоп торговли (live-статус + управление)  
- тикер должен быть в вселенной  
- доля бумаги  
- доля рукава  
- дневной убыток  
- один вход на бар  
- день отчёта  

Каждая карточка: название · «зачем» · «что увидите при отказе».

**Тур:** вселенная → стоп → почему ордер режут.

## C8. Журнал `#/journal`

**Intro:** «Факт лабораторной истории: ордера и проводки книги.»

### Ордера
Фильтры: статус, рукав, тикер.  
Колонки: время · тикер · сторона · кол-во · статус · причина · рукав.  
Статусы по-русски.

### Проводки
Колонки: время · счёт · сумма · причина · ссылка/ref.  
Причины: депозит, комиссия, сделка, сейф, …

**Тур:** ордер vs проводка → где искать отказ → связь с Портфелем.

## C9. Помощь `#/help`

Блоки:
1. Карта кабинета (8 пунктов — зачем каждый)  
2. Легенда пиллов  
3. Словарь  
4. Безопасность (что никогда не вводится в браузер)  
5. Управление обучением: сбросить все туры / пройти тур Обзора сейчас  
6. Ограничения продукта (честный список)

# Часть D. Обучение — спецификация движка

## D1. Требования к движку тура

- Оверлей + подсветка якоря (`data-tour` id)  
- Шаги: заголовок, текст, кнопки «Назад» / «Далее» / «Закрыть»  
- Focus trap умеренный (можно закрыть Esc)  
- Не перекрывать опасную кнопку Стоп так, чтобы её нельзя было нажать вне тура  
- Прогресс «шаг 2 из 5»  
- Хранение: `localStorage` ключ `cabin_tour_v1:{route}`  
- Сброс всех ключей из Помощи  
- Автостарт только при первом заходе в раздел и только если токен уже принят  
- На мобиле тур не должен требовать hover  

## D2. Контент туров — минимальный объём

| Раздел | Мин. шагов | Обязательные якоря |
|---|---|---|
| Вход | 2 | поле токена, кнопка входа |

# Часть F. Микрокопирайт (банк формулировок)

Использовать близко к тексту (можно править стиль, нельзя ухудшать смысл).

**Обзор, empty очереди (агенты выкл):**  
«Очередь пуста: агенты выключены. Это ожидаемо. Когда включите `AGENTS_ENABLED`, предложения появятся здесь.»

**Обзор, empty очереди (агенты вкл):**  
«Новых предложений нет. Когда агент что-то предложит, вы увидите карточку и бейдж в шапке.»

**Стоп confirm:**  
Заголовок: «Остановить торговлю?»  
Текст: «Новые ордера будут отклоняться правилами риска. Уже открытые позиции этим действием автоматически не закрываются.»  
Кнопки: «Остановить» / «Отмена»

**Снять стоп confirm:**  
«Снова разрешить новые ордера? Риск-правила (вселенная, доли, дневной лимит) продолжат действовать.»

**Принять proposal:**  
«Принять предложение? Дальше сработают риск-правила. Если правило не пропустит — вы увидите причину.»

**Paper disclaimer (портфель):**  
«Цифры из лабораторной книги (paper). Это не баланс экрана Тинькофф Инвестиций.»

# Часть G. Визуал и плотность

## G1. Токены

- Фон: графит с тёплой оливковой температурой (не синий «saas», не фиолетовый «ai»)  
- 1 elevation для панелей  
- Акцент ok: приглушённый зелёный  
- Attention: янтарь  
- Danger: только стоп/отклонение/ошибка  
- Шрифт UI: distinctive humanist sans (не Inter/Roboto/Arial как единственный)  
- Числа: mono tabular  
- Радиус 8–10px единый  
- Motion: появление бейджа очереди; смена пилла стопа; переход тура (150–200ms)

## G2. Плотность

- Обзор: воздушнее, крупные метрики  
- Журнал/вселенная: плотные таблицы  
- Не больше **4** крупных KPI в одном ряду  
- Карточка proposal: min height достаточна для summary+actions, без простыни

## G3. Mobile

- Меню: bottom tabs (основные 5) + «Ещё» (Новости/Рынок/Помощь) **или** burger с теми же 8  
- Таблицы: horizontal scroll, липкий первый столбец где критично (тикер)  
- Туры читаемы без pinch zoom
